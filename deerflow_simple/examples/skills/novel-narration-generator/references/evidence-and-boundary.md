# 证据追溯与边界处理

本参考文件是 Skill 的**底线保障**：
- 让每一句"事实"都能追溯到索引中的 Claim 或原文锚点；
- 让每一句"推断"都明确标识为推断；
- 让 Skill 在"数据不全/歧义/冲突/预算不足"等边界情况下给出稳健产出或清晰拒绝。

---

## 一、证据层级与叙述口吻

### 1.1 三级证据分层

索引中的 `claim.certainty` 字段决定了稿件中可用的叙述口吻：

| 证据级别 | 含义 | 稿件中允许的叙述口吻 |
|---|---|---|
| `explicit` | 原文叙述 / 作者旁白 | **直接客观陈述**（"他杀了师父"） |
| `reported` | 书中某角色的说法 | **带归属的转述**（"按门主的说法，他杀了师父"） |
| `inferred` | 索引建立者的推断 | **推测口吻**（"从几次见面的间隔推测，他们应该还有联系"） |
| 无依据 | 索引中没有对应 claim | **解说腔**（"仿佛/或许/读者或许会想起……"） |

**升格禁令**：
- `reported` → `explicit`：**严禁**。不要把"某人说"写成"事实是"。
- `inferred` → `explicit`：**严禁**。不要把"推测"写成"确凿"。
- 无依据 → 任何级别：**严禁**。情绪渲染必须留在解说腔。

### 1.2 事实 vs 解读的分工

| 稿件中的句子类型 | 要求 |
|---|---|
| **客观事实**：谁做了什么、谁对谁说了什么、什么规则生效 | **必须**在索引中有对应 `claim-*`（explicit 或 reported）；凭记忆或推理生造 **不允许** |
| **解读 / 推断**：这背后体现了什么、意味着什么 | 允许用"**解说员视角**"（"从中可以看出……"）；但**必须建立在至少一条 explicit claim 之上**；不得把推断写成既成事实 |
| **情绪渲染 / 氛围描写**：画面感、读者感受 | 若无对应 claim，**必须**使用"仿佛 / 或许 / 读者会不由自主地想起"等解说腔；禁止用确定性语气表述为事实 |

### 1.3 对应示例（三种口吻并列）

**索引支撑**：
- `claim-00042`（explicit）："他离开山门后再未归来。"
- `claim-00088`（reported，来自第 134 章门主旁白）："门主说，他是因为师门压力才离开的。"
- 索引无记录："他离开那天山下在下雪。"

**正确稿件写法**：

> 他离开山门后再未归来。
>
> 门主在后来的朝会上曾经说起过这件事：**他是因为师门压力才离开的**。可书里其他地方从没给过这一说法第二个佐证。所以这更像是门主的一面之词，而不是定论。
>
> 据说那一天山下还在下雪。原文没写过这一笔，可每次读到这里，读者或许都会不由自主地想象那样一场雪——漫天都是、落无声响。

## 二、揭示顺序：`revealed_at` 与 `supersedes_refs`

### 2.1 `revealed_at` 的使用

- `revealed_at` 标注的是**这条信息在哪一章对读者揭示**。
- 一期固定 `mode=full`：**可以使用**后文揭示的真相；但**必须**按信息揭示顺序叙述。
- 处理口诀：
  - 当讲述章节位置 **< `revealed_at`** 时 → 用"**后来才揭示**"口吻（"他当时并不知道，几年后他将面对的……"）。
  - 当讲述章节位置 **≥ `revealed_at`** 时 → 可以作为既成事实叙述。
- **禁止**：把 `revealed_at = 第 200 章` 的真相，无痕写进第 20 章的解说正文作为当时的既知。

### 2.2 `supersedes_refs` 的处理

- 若一个 Claim 存在 `supersedes_refs`（它取代了之前的某个旧 Claim），说明小说后文**修正或翻转**了早先的结论。
- 处理规则：
  1. 稿件采用**最新 revision 的 Claim**作为"真相版本"。
  2. 讲述该事件时，**先讲当时所知**（旧 Claim 的内容），**再讲后来真相**（新 Claim 的内容）。
  3. **不得**用后文认知无痕覆盖早期场景的叙述。
  4. 在证据脚注中标注"存在版本冲突，已采用较新 revision"。

### 2.3 身份、能力、组织归属

对身份揭示型 Claim（`identity_links`、能力归属、组织归属）尤其严格：
- `revealed_at` 之前：角色依旧使用当时的身份称呼；
- `revealed_at` 之后：可以使用新身份；但要在首次出现"新身份"时点一句"（后来才被揭示）"。

## 三、证据脚注清单

### 3.1 格式规范

稿件正文之后、元信息之前，用 `---` 分隔线隔开，加入 "## 证据脚注" 区块：

```
## 证据脚注

- 结论："主角在此役后彻底与师门决裂"
  - claim-00042（explicit）
  - 关键事件：ev-00117
  - 原文锚点：vol-03/ch-0085:L120-L138

- 结论："A 对 B 存在明显庇护倾向"
  - claim-00088（reported，来自第 134 章门主旁白）
  - 关键事件：ev-00201
  - 原文锚点：vol-04/ch-0112:L45-L60

- 结论："夺气诀的冷却周期大于一甲子"
  - claim-00301（inferred，由索引建立者基于三次使用间隔推测）
  - 相关事件：ev-00401 / ev-00512 / ev-00643
  - 原文锚点：无（无单一锚点）

- 版本冲突说明：
  - claim-00042 曾有旧版结论"因家族压力离开"（revision-1），已采用较新 revision-2 结论"因师门决裂离开"
```

### 3.2 覆盖的最小集合

证据脚注至少要覆盖：
- 所有在正文中被叙述为"**客观事实**"且被用作关键转折支撑的结论；
- 所有被引用的 `reported` 结论（必须标明归属角色与出处章节）；
- 所有版本冲突（标注取舍）；
- 所有"证据有限（无锚点）"的 Claim。

### 3.3 保留 / 剥离策略

- Skill **默认保留**证据脚注，便于下游核验。
- 调用方可通过 `include_footnotes=false` 要求剥离。
- 即便剥离，正文内也**不得**出现"显然"、"毫无疑问"这类无依据的强判断——证据脚注剥离不等于证据可以消失。

## 四、边界情况应答矩阵

本矩阵集中列出常见失败模式及**标准应答模板**。LLM 遇到对应情况时，直接按模板响应，不要擅自创作。

### 4.1 `subject` 在名称分片中无命中

**触发条件**：`navigation/names/part-*.json` 中无与 subject 字符串精确匹配的 name/alias。

**标准应答**（取代稿件返回）：

```json
{
  "error": "subject_not_found",
  "message": "未在索引中找到名称：{subject}。",
  "nearest_candidates": [
    {"ref": "char-00017", "name": "韩立", "part": "names/part-h.json"},
    {"ref": "char-00122", "name": "韩云峰", "part": "names/part-h.json"}
  ],
  "advice": "请确认拼写或从以上候选中选择一个 ref 作为 subject 再次调用。"
}
```

### 4.2 `focus_ranges` 内所有相关章节 `coverage.topics[task_type]=not_analyzed`

**触发条件**：目标范围的覆盖状态全部为 `not_analyzed`，索引层面无材料可用。

**标准应答**（取代稿件返回）：

```json
{
  "error": "coverage_not_analyzed",
  "message": "focus_ranges 覆盖的章节 {from}~{to} 对于 task_type={task_type} 尚未索引。",
  "coverage_status": "not_analyzed",
  "advice": "可选操作：1) 等待索引建立；2) 换一个已覆盖该范围的 task_type；3) 让解说范围退到最近一次 complete 的区间，由调用方确认。"
}
```

**严禁**：从原文直接硬凑生成——这超出了 Skill 的只读消费定位（原文回读仅用于**佐证**索引结论，而非替代结论）。

### 4.3 同一事件在不同主题索引中结论冲突

**触发条件**：同一 `ev-*` 在不同主题的 Claim 中出现结论不一致，或某 Claim 有 `supersedes_refs` 但其他主题的索引仍引用旧 Claim。

**处理策略**：

1. **优先采用**：带有最新 revision 的 Claim（`revision` 字段最大者）。
2. **稿件正文**：按最新结论叙述，不特意暴露冲突。
3. **证据脚注**：添加"版本冲突说明"条目，标明被取代的旧 Claim 与采用的新 Claim。
4. **元信息**：在 `meta.coverage_gaps` 中加一条 "detected claim conflict: {ev_id}，已采用较新 revision"。

### 4.4 收到 `mode=cutoff` 或"严格防剧透"参数

**触发条件**：调用方传入了 `mode=cutoff`、`strict_spoiler_free=true`、`as_of_strict=true` 等一期不支持的参数。

**标准应答**（取代稿件返回）：

```json
{
  "error": "unsupported_parameter",
  "message": "一期（v1.0.0）仅支持 mode=full，不支持严格防剧透投影。遵循 novel-index-templates.md §10 一期视角。",
  "received_parameter": "mode=cutoff",
  "advice": "请改用 mode=full（默认）调用；如需真正的严格剧透隔离，请等待 v2 版本。"
}
```

**严禁**：假装支持而降级处理（例如静默返回一个看起来像"cutoff"的稿件）。

### 4.5 累计材料接近 `task_token_budget` 的 90%

**触发条件**：加载过程中累计 token 接近预算上限。

**处理策略**：

1. **立即停止扩展加载**（不再读取新的可选材料）。
2. **优先牺牲"文采修饰"而非"证据保留"**：
   - 若核心结论仍缺证据 → 删减正文的点评与过渡段，为锚点回读留出空间；
   - 宁可输出 1200 字的紧凑稿，不要输出 1500 字但未核验结论的稿件。
3. **元信息**：`meta.budget_truncated = true`；在 `meta.coverage_gaps` 中列出"因预算限制未纳入"的材料范围。
4. **正文结尾**：**不**要专门为此加说明段；由元信息承担交代责任。

### 4.6 `extra_hint` 要求了索引无依据的内容

**触发条件**：用户提示"重点讲 XX 的童年"，但该人物索引里并无童年阶段材料。

**标准应答**（部分成功 + 显式说明）：

- 正文：按**索引中已有**的材料正常生成（例如从"少年时期"开始讲），**不**凭空补"童年"段。
- 正文末尾加一段："> 关于 `extra_hint` 中提到的「童年」部分，索引现阶段没有覆盖；本篇从他有迹可查的少年时期开始讲起。"
- 元信息 `meta.coverage_gaps` 添加："extra_hint 要求的「童年」在索引中无覆盖"。
- 并给出 **1–2 条可替代的近邻侧重点**（例如"少年入门前的那段流浪经历"），放在元信息的 `meta.alternatives` 字段：

```yaml
meta:
  alternatives:
    - "少年入门前的那段流浪经历（stage-00001 ~ stage-00003）"
    - "初入师门时与师父的几次关键对话（ev-00017 / ev-00024）"
```

## 五、Skill 的只读契约

- **全程只读**：Skill 的任何工具或路径调用都不得对 `novel/` 目录执行写入操作。
- **不触发账本/编号/覆盖的变更**：禁止调用 `coverage.json` 更新、`ids/*` 增号、`ledger/*` 追加等接口。
- **不读取 Skill 目录外的敏感路径**：仅限 `novel_root` 范围内的只读访问。
- 如 LLM 发现自己即将或已经写入 → **立即停止并报错**（这是一期阶段的强约束）。

## 六、输出前的证据与边界勾兑

每次输出前，LLM 必须：

- [ ] 稿件中每一处客观事实均对应 `claim-*`（explicit/reported）；
- [ ] `reported` / `inferred` 的结论**没有被升格**为客观陈述；
- [ ] 无索引依据的情绪渲染均使用解说腔；
- [ ] `revealed_at` 晚于当前讲述章节的结论均已标注"后来才揭示"；
- [ ] 存在 `supersedes_refs` 的事件按信息揭示顺序讲述，并在脚注说明；
- [ ] 证据脚注清单覆盖最小集合（见 §3.2）；
- [ ] 元信息中 `coverage_gaps` / `budget_truncated` / `alternatives` 等字段按实际情况填写；
- [ ] 若命中边界情况，**已按 §4 对应模板返回**，而非擅自产出稿件。
